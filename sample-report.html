🔴 Critical S2-KERB-001 Kerberoastable service accounts detected ▼ expand S² — Credential 6 2026-05-15
Description
6 user accounts have Service Principal Names (SPNs) configured, making them Kerberoastable. An attacker with any valid domain credentials can request a Kerberos service ticket for these accounts and attempt to crack the password hash offline — with no noise on the network and no account lockout risk.
Evidence
SamAccountName      SPN                              PasswordAge
---                 ---                              -----------
svc_sql             MSSQLSvc/db01.alpha-inv.co.ke    847 days
svc_backup          BackupExec/bkp01.alpha-inv.co.ke 1,203 days
svc_erp             HTTP/erp.alpha-inv.co.ke         612 days
svc_reports         HTTP/reports.alpha-inv.co.ke     945 days
helpdesk_admin      HTTP/helpdesk.alpha-inv.co.ke    388 days
svc_monitoring      WSMAN/mon01.alpha-inv.co.ke      721 days
Remediation
1. Audit each SPN — remove any that are not actively required. 2. Migrate all service accounts to Group Managed Service Accounts (gMSA) — passwords rotate automatically (240-character, machine-managed). 3. For accounts that cannot use gMSA: reset passwords to 25+ character random strings immediately and enforce AES-only Kerberos encryption (remove RC4). 4. Enable "Protected Users" security group for all service accounts where possible. Priority order: svc_sql and svc_backup first (oldest passwords, highest-privilege services).

🔴 Critical S2-KRBT-001 KRBTGT password not rotated in over 3 years ▼ expand S² — Credential 1 2026-05-15
Description
The KRBTGT account password was last changed 1,247 days ago (approximately 3.4 years). The KRBTGT hash is used to sign all Kerberos tickets in the domain. A compromised KRBTGT hash enables a "Golden Ticket" attack — allowing an attacker to forge Kerberos tickets for any user, including Domain Admins, with arbitrary lifetimes, even after passwords are reset.
Evidence
KRBTGT Account:
  PasswordLastSet : 2023-01-18 08:33:12
  PasswordAge     : 1,247 days
  Recommendation  : Rotate every 180 days maximum
  Golden Ticket   : Risk window OPEN since Jan 2023
Remediation
Follow Microsoft's KRBTGT reset procedure exactly — this must be done in two stages to avoid authentication disruptions: Stage 1: Reset KRBTGT password (run during maintenance window). Stage 2: Wait 10 hours (replication convergence + ticket expiry). Stage 3: Reset KRBTGT password a second time. After reset: establish a recurring 180-day rotation schedule. Document as a change management item. Verify all DCs have replicated before closing the maintenance window. ⚠ Do not reset the KRBTGT password during business hours — schedule a maintenance window.

🟠 High S3-UDEL-001 Unconstrained delegation configured on 2 servers ▼ expand S³ — Delegation 2 2026-05-15
Description
Two non-DC servers have "Trust this computer for delegation to any service (Kerberos only)" — unconstrained delegation — enabled. When a user authenticates to a server with unconstrained delegation, their TGT is stored in that server's memory. An attacker who compromises either server can extract these TGTs and impersonate any user who has recently authenticated to it, including Domain Admins.
Evidence
Servers with Unconstrained Delegation (non-DC):
APP01.alpha-inv.co.ke  — Application server
LEGACY01.alpha-inv.co.ke — Legacy ERP server

TrustedForDelegation = True
TrustedToAuthForDelegation = False
Remediation
1. Migrate from Unconstrained to Constrained Delegation (KCD) — specify only the services each server legitimately needs to impersonate users for. 2. If Resource-Based Constrained Delegation (RBCD) is feasible, prefer it — it can be configured without domain admin rights. 3. Add both servers to the "Protected Users" group — this prevents TGT forwarding entirely if no delegation is actually needed. 4. Review whether LEGACY01 genuinely requires delegation — if the ERP system does not use Kerberos pass-through, delegation can be disabled entirely. 5. Enable monitoring for TGT-forwarding events (Event ID 4768, 4769) from these servers.

🟠 High S2-WKEP-001 Weak Kerberos encryption — RC4 still permitted domain-wide ▼ expand S² — Credential Domain-wide 2026-05-15
Description
The domain permits RC4-HMAC Kerberos encryption in addition to AES-128 and AES-256. RC4 is a weak cipher with known cryptographic weaknesses. When Kerberoasting attacks capture service ticket hashes, RC4-encrypted tickets are significantly faster to crack than AES tickets. Additionally, RC4 support enables downgrade attacks where an attacker can force weaker encryption to be negotiated.
Evidence
Domain: alpha-inv.co.ke
  msDS-SupportedEncryptionTypes: 0x7 (RC4, AES128, AES256)
  RC4_HMAC_MD5 enabled: True  ← WEAK

Accounts using RC4 only (no AES flag):
  17 service accounts
  3 legacy computer accounts
  Encryption not set (defaults to RC4): 41 accounts
Remediation
1. Set msDS-SupportedEncryptionTypes = 0x18 (AES128 + AES256 only) on all service accounts. 2. Update the Default Domain Policy Kerberos settings to require AES encryption. 3. Set "Network security: Configure encryption types allowed for Kerberos" GPO to AES128 and AES256 only (remove RC4, DES). 4. For the 41 accounts with no encryption type set: run Set-ADUser with -KerberosEncryptionType AES128,AES256. 5. Test legacy applications for compatibility before disabling RC4 domain-wide — some older systems may require a phased migration. 6. After migration: reset all service account passwords to invalidate existing RC4 ticket hashes.

🟡 Medium S1-ADMC-001 AD Recycle Bin not enabled ▼ expand S¹ — Identity Domain 2026-05-15
Description
The Active Directory Recycle Bin is not enabled. Without it, accidentally deleted objects (users, groups, OUs, GPOs) cannot be recovered without a full AD restore from backup — which requires a domain controller reboot into Directory Services Restore Mode. The Recycle Bin allows recovery of deleted objects with all attributes intact for up to 180 days, with no service interruption.
Remediation
Enable the AD Recycle Bin immediately (one-time, non-reversible, zero-downtime operation): Enable-ADOptionalFeature "Recycle Bin Feature" ` -Scope ForestOrConfigurationSet ` -Target "alpha-inv.co.ke" ` -Confirm:$false Note: This requires Forest Functional Level 2008 R2 or higher. Verify with: Get-ADForest | Select ForestMode Note: This is irreversible — once enabled, cannot be disabled without raising the forest FFL.
